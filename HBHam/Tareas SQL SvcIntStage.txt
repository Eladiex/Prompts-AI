# 📘 Reglas y Definiciones – Generación de Scripts SvcIntStage

## 🧩 General
Este documento resume las reglas definidas para la generación de tablas, stored procedures y scripts SQL basados en tablas *SvcIntStage*.

---

## 🔨 Tarea 1 – Creación de Tablas SvcIntStage

### Reglas:
- Todo comentario debe venir en Inglés
- Nombre de la tabla: `<NombreTabla>SvcIntStage`
- Campo Identity:
  - Tipo: BIGINT IDENTITY(1,1)
  - Nombre: `<NombreTabla>SvcIntStageID`
- Campos obligatorios:
  - `SvcIntRequestID VARCHAR(36) NOT NULL`
  - `TrxActionID TINYINT NOT NULL`
- Se incluyen todos los campos de la tabla original.
- Se agrega PRIMARY KEY sobre el campo Identity.
- Se crean índices en la tabla:

CREATE NONCLUSTERED INDEX [IX_<NombreTabla>SvcIntStage] ON [dbo].[<NombreTabla>SvcIntStage]
(
	[SvcIntRequestID] ASC
)WITH (PAD_INDEX = OFF, STATISTICS_NORECOMPUTE = OFF, SORT_IN_TEMPDB = OFF, DROP_EXISTING = OFF, ONLINE = OFF, ALLOW_ROW_LOCKS = ON, ALLOW_PAGE_LOCKS = ON, OPTIMIZE_FOR_SEQUENTIAL_KEY = OFF) ON [PRIMARY]
GO

ALTER TABLE [dbo].[<NombreTabla>SvcIntStage] ADD  CONSTRAINT [PK_<NombreTabla>SvcIntStage] PRIMARY KEY CLUSTERED 
(
	[<NombreTabla>SvcIntStageID] ASC
)WITH (PAD_INDEX = OFF, STATISTICS_NORECOMPUTE = OFF, SORT_IN_TEMPDB = OFF, IGNORE_DUP_KEY = OFF, ONLINE = OFF, ALLOW_ROW_LOCKS = ON, ALLOW_PAGE_LOCKS = ON, OPTIMIZE_FOR_SEQUENTIAL_KEY = OFF) ON [PRIMARY]
GO

**Dejar el índice en ese formato, ya que reduce campo a nivel del archivo donde se respaldan.**

## 🧩 Tarea 2 – Stored Procedures

### Tipos:
- Insert
- Update
- Delete
- Select

### Reglas generales:
- Todo comentario debe venir en Inglés
- Nombre:
  - `spSvcInt_<NombreTabla>SvcIntStage<Acción>`
  - Ejemplo: `spSvcInt_RefundsNVoidsSvcIntStageSelect`
- Parámetros adicionales obligatorios (excepto en Select):
  ```
  @MQOriginatingLocationID INT = 5001,
  @MQOriginatingComputerID INT = 0,
  @MQTrxDate DATETIME = NULL
  ```
- No duplicar parámetros si ya existen.
- No incluir estos parámetros en SELECT.
- No usar `RETURN 0`.
- `SET NOCOUNT ON` obligatorio.
- Para SP con acción Insert:
  - Obtener consecutivo siguiente sólo si el valor de @<NombreTabla>ID viene vacío:
	If @<NombreTabla>ID is Null or @<NombreTabla>ID = 0
	Begin
			--Get @<NombreTabla>ID from Counter table
			Update Counter<NombreTabla> set Counter = Counter + 1, @<NombreTabla>ID = Counter where KeyFld = 1
	End

  - Usar valor de consecutivo en @<NombreTabla>ID

		Set @Inserted = -1

		--Create OrderLog record
		--handling in Service
		--exec sp_OrderLogInsert @TableName = 'OrderDetail', @TableID = @OrderDetailID, @EmployeeID = @DataEntryEmployeeID, @TrxTypeID = 'I', @TrxDateTime = @CurrentDate

		Select @Status AS [status], * From OrderDetailSvcIntStage Where OrderDetailID = @OrderDetailID
	End Try

	Begin Catch
		If @Inserted = -1
			Begin
				Select @Status AS [Status], @OrderDetailID as OrderDetailID
			End
		Else
			Begin
				SET @Process = ERROR_PROCEDURE() + ' @ Line=' + CONVERT(VARCHAR, ERROR_LINE())
				SET @ErrMsg = 'spSvcInt [' + CONVERT(VARCHAR, ERROR_NUMBER()) + '] ' + ERROR_MESSAGE() + '  : OrdersID: ' + convert(varchar, @OrdersID)

				EXEC spInterfaceErrorINSRT @Process,@ErrMsg,-1 -- Always log and send email
				SET @Status='Failed'

				Select @Status AS [Status], -911 as OrderDetailID

				-- Most of the time you're done.
				Set @ErrMsg = @Process +  ':' + @ErrMsg
				;Throw 90911, @ErrMsg, 1;
			End

	End Catch

END

### 📥 INSERT
- Fuente: `SvcIntStage`
- Filtro:
  ```
  TrxActionID = 1
  AND SvcIntRequestID = @SvcIntRequestID
  ```
- Columnas deben ser explícitas (NO `SELECT *`)

---

### 🔁 UPDATE
- Fuente: `SvcIntStage`
- Filtro:
  ```
  TrxActionID = 2
  AND SvcIntRequestID = @SvcIntRequestID
  ```
- Uso obligatorio de CTE:
  ```
  WITH TablaCTE AS (...)
  ```
- Join por ID principal.
- Columnas explícitas en SELECT.

---

### ❌ DELETE
- Fuente: `SvcIntStage`
- Filtro:
  ```
  TrxActionID = 3
  AND SvcIntRequestID = @SvcIntRequestID
  ```
- Eliminación basada en IDs.

## 📌 Convenciones Importantes

- ❗ Nunca usar `SELECT *`
- ✔ Siempre listar columnas explícitamente
- ✔ Usar alias (`S`, `T`, etc.)
- ✔ Usar `WITH (NOLOCK)` en lecturas
- ✔ Mantener consistencia en nombres
- ✔ Respetar estructura de plantillas

- Agregar comentario a la creación de Store Procedures siguiendo esta estructura:
-- =============================================
-- Author: Eladio Valverde
-- Create date: <Fecha Actual. Formato: dd/mm/yyyy>
-- Description:	<descripción de la acción del SP en inglés. Ejemplo: To insert into the staging table for Refunds and Voids>
--
-- Last modified (newer first): 
-- dd/mm/yyyy Initials: Razon 
--    
-- =============================================

```
	@DataEntryEmployeeID int = 0,
	@OrderPaymentID Decimal (18,9) = 0, 
	@OrderPaymentSeq Int = 0, 
	@OrdersID Decimal (18,9) = 0, 
	@PaymentMethodID Int = 0, 
	@PaymentInfo1 Varchar (25) = Null, 
	@PaymentInfo2 Varchar (25) = Null, 
	@PaymentInfo3 Varchar (100) = Null, 
	@PaymentAmount Money = 0,

BEGIN

	DECLARE @Process varchar(500), @ErrMsg varchar(5000), @Status varchar(25)='success'
```
